# Provenance correction: volatile Open-Meteo ERA5 response metadata versus actual daily climate values

**2026-10-19 | ODSP PR #267 | source-level diagnostic / scientific inferential integrity, NOT a biological new finding.**

The first six-cohort **within-animal-year rank association** source route [CI 39218182379](https://github.com/zuizui0223/odsp/actions/runs/39218182379) passed all six known-truth source/sampling tests but correctly returned **six of six SOURCE HOLD** and **zero newly admissible Spearman outcomes**, after rereading the actual six original GPS files. Every original source GPS cohort animal count/effect and published coarse regional ERA5 **cohort-mean** thermal and preceding-water proxy contrast replicated to the prior 1e−10 guard, before a *raw downloaded API-response body* SHA256 comparison failed for every source. **Do not promote the failed six rho results or claim climate values changed from the SHA failure alone.** The original source-level GPS/ERA5 and separately reported univariate individual-year OLS slopes remain unchanged.

### Identified same-URL API envelope variability

Two separate publicly fetched source responses for the *same exact original* Florida 287-calendar-day Open-Meteo ERA5 URL, with the original source variables `temperature_2m_mean`, `precipitation_sum` and `et0_fao_evapotranspiration`, returned different `generationtime_ms` header values: **2.084970474243164 vs 2.16829776763916**. Both responses were for **2020-01-16 through 2020-10-28** (287 daily dates) with identical sampled daily temperature endpoints **23.4°C** and **27.5°C**. The raw JSON byte SHA256 is therefore NOT a stable scientific daily climate-data fingerprint even if day-level climate arrays match. This single diagnostic alone does **not** prove complete day-array identity to 2026-10-19 first original retrievals, because those originals retained only RAW SHA256 and group-mean summaries, not full daily arrays.

### Separate versioned repair, without silent original-result change

The new [source-scientific-content-only contract](../research/MOVEBANK_WITHIN_ANIMAL_ERA5_CANONICAL_SOURCE_V1_20261019.json) and [v1 reader](../scripts/movebank_six_source_within_animal_era5_canonical_v1.py) preserve:

1. All six original provider ORIGINAL bitstream MD5s, original eligible individuals (197 total), individual-year/daylight matching and source-group GPS effects **unchanged**.
2. The original six cohort-mean matched-date `ΔT` and `Δ30d(P−ET0)` scientific values must still match the previously archived v0 means to 1e−10 and have no unexpected missing matched-weather pairs. A mismatch produces a scientific SOURCE HOLD before any new rank analysis.
3. The new **v1 SOURCE SNAPSHOT** records full original dated ERA5 scientific daily arrays, source units, provider grid and timezone, and a SHA256 over sorted-key compact JSON containing exactly these science fields. The variable `generationtime_ms` is excluded (and its presence recorded) as transport metadata, **not a hydroclimate variable**.
4. Unlike the earlier v0 raw-envelope digest, v1 daily scientific-source hash is stable when only `generationtime_ms` differs. Its tests deliberately fail if even one original climate value/date/unit changes; the original v0 source SHA/HOLD remains archived unchanged.
5. With this new *separately labeled daily scientific source version*, re-evaluate only the **original unchanged exploratory rank association** of paired source temperature or modeled water-proxy contrasts versus observed individual-year paired GPS NIGHT−DAY relative displacement. This is explicitly a **post-first-result rank robustness check** against already published univariate least-squares results, not a new untouched biological test.

Tests [source v1](../tests/test_movebank_six_era5_canonical_source_v1.py) plus [original six v0](../tests/test_movebank_six_source_within_animal_era5_v0.py) and dedicated new [GitHub Actions run](https://github.com/zuizui0223/odsp/actions/runs/39220116497) document the attempt; when that run is pending or fails, all new Spearman values remain UNAVAILABLE.
