# Pre-outcome external freeze workflow v1

## Goal

Untouched external validation is only persuasive if the analysis is fixed before
external outcomes are available. ODSP therefore provides a separate freeze step
that runs on an outcome-free row roster and an explicit analysis plan.

## 1. Prepare an outcome-free roster

The roster must contain exactly one column: the external `row_id`. Duplicate row
IDs are rejected. Outcome, score, label, treatment or other columns are not
allowed in this file.

This allows the final external cohort to be content-addressed without opening the
validation outcomes.

## 2. Prepare the freeze plan

The plan fixes:

- upstream model-set ID;
- external dataset ID;
- roster path and row-ID column;
- exact upstream refit IDs and reference refit;
- proper-score semantics;
- strict information filtration;
- one-sided alternative;
- familywise confidence level;
- bootstrap draw count and seed;
- minimum refits and validation blocks;
- gain tolerance.

The plan schema intentionally has **no freeze timestamp field**.

## 3. Generate the freeze artifact

```bash
odsp freeze-refits-external \
  --plan freeze-plan.json \
  --manifest-out freeze.json \
  --out freeze-receipt.json
```

ODSP sets `frozen_at_utc` from the runtime UTC clock, computes the external row
roster SHA256, writes the semantic manifest and returns its SHA256 in the freeze
receipt. An existing manifest path is never overwritten.

The runtime clock is not an independently trusted timestamp authority. For a
stronger provenance chain, the generated manifest/hash can additionally be
committed to a timestamped version-control or archival system before outcomes are
opened. ODSP itself does not claim such third-party attestation.

## 4. After the freeze, score the untouched outcomes

Upstream software may then produce one score table row per `refit_id × row_id` on
the untouched validation outcomes. The final external endpoint contract points to
the frozen manifest and its SHA256.

## 5. Run final validation

```bash
odsp transfer-refits-external \
  --contract external-endpoint.json \
  --out external-receipt.json
```

The semantic-lock validator requires the runtime external row roster, refit IDs,
reference refit, score semantics, information filtration and every inferential
setting to match the pre-outcome manifest exactly.

## Boundary

The generator guarantees that ODSP did not accept outcome columns in its freeze
roster and that the timestamp was generated by the running process rather than
supplied as a plan field. It cannot prove that external outcomes were unavailable
through some other channel, nor that the host system clock was trustworthy.
